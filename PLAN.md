# PLAN.md — план работ

Трек 2, Модель Z. Цель: максимальный ЧДД на валидационном кейсе при том, что
организаторы пересчитают наш `wells_schedule.inc` **один раз** и сравнят с заявленным.

## Рабочие потоки

| Поток | Содержание | Префикс коммитов |
|---|---|---|
| ГГДМ | дек, SUMMARY, запуск симулятора, выгрузка результатов | `sim:` |
| Экономика | обвязка эталонного расчётчика ЧДД, нормативы, паритет | `eco:` |
| Расписание | генерация и валидация `wells_schedule.inc` | `sch:` |
| Суррогат | DoE, датасет прогонов, обучение, метрики, границы применимости | `srg:` |
| МАС | агенты, оптимизация, логика решений, объяснимость | `mas:` |
| UI | веб-платформа, визуализация | `ui:` |
| Документация | отчёт, README, презентация, журнал экспериментов | `docs:` |
| Инфраструктура | окружение, зависимости, CI, Docker | `infra:` |

## Критический путь

```
симулятор запускается на Model_Z
        ↓
базовый прогон истории → выгрузка 14 колонок → ЧДД базового сценария   ← точка отсчёта
        ↓
генератор wells_schedule.inc + валидатор (читается моделью, ограничения соблюдены)
        ↓
DoE: N прогонов с разными управлениями → датасет
        ↓
суррогат (прогноз добычи/закачки по управлению) + метрики + границы применимости
        ↓
МАС поверх суррогата → кандидат-расписание → ПОЛНЫЙ расчёт → заявленный ЧДД
        ↓
UI + документация + Docker
```

**Всё упирается в первый шаг.** Пока на месторождении нельзя посчитать ни один
сценарий, у нас нет ни базовой цифры, ни данных для суррогата. Поэтому запуск
симулятора — задача №1 и не делится на «потом доделаем».

## Риски

| Риск | Чем бьём |
|---|---|
| Расхождение нашего ЧДД с расчётом организаторов → дисквалификация | считаем только вендоренным эталоном; заявляем консервативный прогон; сверяем формат `.inc` заранее |
| Нет доступного симулятора на машинах команды | OPM Flow в VirtualBox-VM для первого прогона + облачная VM под DoE, см. `docs/setup-simulator.md` |
| Локального железа не хватает на датасет суррогата (2 ядра, Pentium G3220) | облако; рестарт с 01.01.2007 срезает ~40 % каждого прогона |
| Суррогат уводит оптимизатор в область, где он врёт | детектор выхода за диапазон + обязательная перепроверка полным расчётом |
| Формат `wells_schedule.inc` и состав фильтра скважин в выгрузке | вопросы В-03 и В-04 трекеру, см. `docs/decisions.md` |
| Валидационный кейс приходит с новыми ограничениями | ограничения — данные конфига, не константы в коде |
| UI и документация «на потом» | они в обязательном пакете: нет UI — нет допуска |
