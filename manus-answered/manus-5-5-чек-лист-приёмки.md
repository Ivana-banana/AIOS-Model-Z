# Чек-лист приёмки условий валидационного кейса

**Правило:** до первого оптимизационного расчёта на каждый пункт должна быть ссылка на место в ТЗ/файле, значение, единица, период и результат проверки. Если ответ отсутствует, писать **«не найдено»** и фиксировать риск.

| № | Вопрос к ТЗ/данным | Ответ/значение | Чем подтверждено | Чем грозит неверный ответ |
|---:|---|---|---|---|
| 1 | Каков точный состав фонда и имена скважин? |  | Дек, выгрузка, список фонда | Потеря скважин, дубли, отказ расчётчика или неверный ЧДД |
| 2 | Какие скважины добывающие, нагнетательные, остановленные и неизменяемые? |  | Секции управления и история | Перепутанная полярность rate/BHP и неверное расписание |
| 3 | Какие скважины разрешено изменять (`controllable wells`)? |  | Дословный пункт ТЗ и diff строк | Изменение запрещённого фонда и несоответствие baseline |
| 4 | Что означает строка расписания: скважина × месяц, сутки, квартал или иной шаг? |  | Календарь, формат файла, пример | Неверная экономика, OPEX и перевод суточных лимитов в объём |
| 5 | Есть ли разрывы дат, неполные месяцы, часовые пояса или особый календарь? |  | Парсер дат и календарная ведомость | Смещение периодов и неправильный годовой лимит |
| 6 | Каковы начало и конец горизонта управления? |  | ТЗ, конфиг, даты в файле | Обрезка расчёта и изменение ЧДД |
| 7 | «Не более X» относится к скважине, группе или объекту? |  | Индекс/область действия в ТЗ | Слишком строгая или слишком слабая срезка |
| 8 | Ограничение — пик в каждый месяц/сутки или среднее за период? |  | Слова `maximum`, `average`, `per month` | Пиковые нарушения проходят по среднему или наоборот |
| 9 | Объём задан за месяц, календарный год, скользящие 12 месяцев или весь горизонт? |  | Границы периода и формула | Перепутаны мощность и накопительный объём |
| 10 | Какой поток ограничен: жидкость, нефть, вода, газ или товарный продукт? |  | Название величины и фазовые поля | Лимит наложен на неверную фазу |
| 11 | В каких условиях измеряется поток: surface/standard/reservoir conditions? |  | Единицы и описание PVT | Ошибка масштаба и несопоставимость с симулятором |
| 12 | Лимит воды относится ко всей закачке, внешней воде, produced water или компенсации? |  | Схема водного баланса | Неправильное распределение источников и двойной учёт |
| 13 | Каковы пределы BHP и THP и где находится точка измерения? |  | Режим скважины и pressure definition | Уставка принята за предел или перепутан знак |
| 14 | Число в управляющем поле — уставка или верхний/нижний предел? |  | Режим `LRAT/ORAT/WRAT/RESV/BHP/THP/...` | Множитель молча закрывает скважину или ослабляет защитный предел |
| 15 | Есть ли минимальная добыча/приёмистость по скважине? |  | Таблица ограничений | Появляются неустойчивые малые режимы и неверная маржа |
| 16 | Есть ли максимум активных скважин? Как выбирать, какие закрывать? |  | Приоритет, маржа, список фонда | Недетерминированный выбор и разные результаты при повторе |
| 17 | Есть ли forced shut, обязательные открытые скважины или фиксированные режимы? |  | Маска фонда и schedule diff | Нарушение прямого запрета, даже если ЧДД выше |
| 18 | Есть ли ограничения пластового давления? Это состояние пласта или BHP? |  | Summary-поля и формула | Rate/BHP ошибочно объявлен эквивалентом пластового давления |

| 23 | Есть ли лимиты внешней воды, электроэнергии, топлива, газа, реагентов? |  | Resource calendar and conversion factors | Rate/BHP не контролирует расход ресурса |
| 24 | Есть ли лимиты закачки за календарный год/период? |  | Годовые суммы с числом дней | Объём ошибочно принят за суточную мощность |
| 25 | Есть ли ремонты, обязательные остановы и ограничения бригад? |  | Maintenance calendar | В расписание попадают запрещённые месяцы |
| 26 | Есть ли минимальная длительность режима, число пусков и переходов? |  | State-transition rules | Нереализуемое частое переключение |
| 27 | Есть ли экологические лимиты по воде, выбросам, факелу, отходам? |  | Permit и методика расчёта | Невозможность доказать соответствие требованиям |
| 28 | Есть ли требования к качеству воды/закачки? |  | Лабораторные данные и диапазоны | Объём воды ошибочно принят за допустимость закачки |
| 29 | Каковы цены, тарифы, CAPEX/OPEX, налоги и валюта? |  | Нормативный файл/таблица | Оптимизируется другая экономика |
| 30 | От какой даты и с каким шагом считается дисконтирование? |  | Формула расчётчика и конфиг | Существенное смещение ЧДД и горизонта |
| 31 | Как трактуется ноль: отсутствие ограничения или нулевой допустимый объём? |  | Явное соглашение в ТЗ | Запрет закачки/добычи может быть проигнорирован |
| 32 | Какие поля обязательны, какие допускают пропуск и каков sentinel для SHUT? |  | Схема файла и валидатор | Пустое поле превращается в ноль или остановку |
| 33 | Каков точный формат сдаваемого файла и независимой проверки? |  | Инструкция организаторов | Формально неверная поставка при верном решении |
| 34 | Какие ограничения должны быть hard, а какие допускают штраф? |  | Критерии оценки | Оптимизатор нарушает дисквалифицирующее условие |
| 35 | Какой базовый сценарий используется для сравнения? |  | Baseline file и расчётчик | Прирост посчитан относительно другой базы |

| 37 | Как будет подтверждена каждая срезка? |  | Лог, summary, тест на нарушающем примере | Нельзя доказать, что ограничение действительно работало |
| 38 | Какие данные отсутствуют по каждому ограничению? |  | Реестр неизвестных | Команда молча подменяет физическое условие прокси |

## Минимальный пакет артефактов до первого расчёта

1. Хэш исходного архива и распакованная неизменяемая копия.
2. Нормализованный реестр ограничений с дословными цитатами.
3. Отчёт о составе фонда, режимах, календаре и единицах.
4. Снимок конфигурации и источников экономических нормативов.
5. Список условий со статусами `реализовано`, `не реализовано`, `не проверяется`, `не найдено`.
6. Минимальные тесты, в которых каждое новое ограничение нарушается ровно одним решением.
7. Базовый прогон, консервативный прогон и полный лог независимой проверки.
8. Список открытых вопросов организаторам и выбранная до ответа безопасная трактовка.

## Критерий приёмки ограничения

Ограничение считается принятым только если одновременно известны его область действия, метрика, оператор, значение, единица, период и источник; оно преобразуется в конкретную проверку или функцию срезки; на тестовом примере нарушение обнаруживается; в рабочем логе видны фактическое значение, предел, период и идентификатор скважины/группы; результат не меняется при отсутствии соответствующего ключа.
