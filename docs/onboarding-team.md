## Первая задача: базовый прогон

Самое ценное, что сейчас можно сделать. Пока нет ни одного расчёта, у нас нет ни
точки отсчёта, ни данных для суррогата, и вся работа идёт на синтетике.

```bash
python scripts/build_case.py                 # соберёт runs/base/RUN.DATA из config.toml
scripts/run_flow.sh runs/base/RUN.DATA 8     # 8 — число процессов
python scripts/export_rows.py runs/base      # проверит расчёт и соберёт rows.csv
```

Базовый кейс — история организаторов как есть, добавлена только наша
SUMMARY-секция (`Model_Z_summary.inc` в поставке пустой, без неё симулятор не
выгрузит ничего).

Третья команда печатает всё, что нужно проверить, и пишет `rows.csv` — им и
обмениваемся: мегабайты вместо сотен мегабайт `.UNSMRY`, и его читает
веб-платформа.

**Что проверить прежде, чем радоваться числу.** Симулятор не падает на том, чего
не понял, — он это пропускает и считает дальше:

1. в логе нет строк про игнорирование ключевых слов (`run_flow.sh` печатает их
   отдельным блоком);
2. накопленная нефть по порядку близка к базовому сценарию организаторов —
   5 011,6 тыс. т по их OPM Flow и 5 036,7 по их тНавигатору (`export_rows.py`
   печатает оба ориентира рядом со своим числом, читая их из `docs/reference/`).
   Ориентир 4 771 тыс. т, стоявший здесь до 01.09, брался из их файла с суффиксом
   `OPTIMIZED` — это другое управление, и сравнение с ним измеряло не то. Ноль
   означает, что скважины остались без соединений с пластом;
3. профили по нескольким скважинам похожи на историю, а не на прямую линию —
   глазами, а не по сводным числам. Для этого поднимается платформа:
   ```bash
   python -m uvicorn aios.web.app:app
   ```

**Что прислать:** `rows.csv`, ЧДД, **время счёта**, число процессов и
характеристики машины, плюс строку в `docs/experiments.md` тем же коммитом.
Время счёта важно не меньше числа: от него зависит, сколько прогонов мы можем
позволить себе на датасет суррогата.

## Что делать дальше, если прогон получился

По `PLAN.md`, веха v0.3: прогнать сценарий бейзлайн-политики и подтвердить
прирост ЧДД полным расчётом. Порядок:

```bash
python -m uvicorn aios.web.app:app     # открыть runs/base → «Запустить цикл»
```

Цикл выдаст расписание с остановкой убыточных скважин и **прогнозный** прирост.
Дальше это расписание считается на ГГДМ — и только после этого прирост можно
называть результатом.

Следом — рестарт на 01.01.2007 (`RESTART` + `SKIPREST`): история 1991–2006 у всех
сценариев одна и та же, её незачем пересчитывать каждый раз. Срезает ~40 % работы
каждого прогона и столько же счёта за облако.

## Чего не делать

Три вещи, каждая из которых стоит дисквалификации или дня работы:

- **Не писать свою формулу ЧДД.** Считает только `vendor/CHDD_PYTHON/`,
  вендоренный побайтово. Обвязка — `aios/economics.py`.
- **Не «чистить» отрицательные приращения** в выгрузке симулятора. Методика
  исключает такие строки из экономики целиком, и так же посчитают организаторы.
  Обнулив их у себя, мы завысим свой ЧДД ровно на те строки, которые у них
  выпадут.
- **Не пересобирать историю SCHEDULE из разобранных структур.** Внутри лежат
  `COMPDAT` — вскрытия пласта во времени. Потеряешь их — скважины останутся без
  соединений, добыча будет нулевой, и симулятор об этом не скажет.

## Ограничения, которые нельзя нарушать

Из разбора организаторов (`docs/method/qa-organisers.md`) — в презентациях этого
нет:

- **давление нагнетания ≤ 300 атм**: выше в жизни раскрываются трещины, хотя
  модель такой режим прекрасно посчитает;
- **дополнительной воды на объекте нет**: закачиваем ту воду, которую подняли,
  накопленная закачка не может превышать добытую;
- дебит жидкости добывающей скважины **≤ 500 м³/сут** (методика);
- вода штрафуется дважды — за подъём в потоке жидкости и за обратную закачку.

Первые три проверяются автоматически: `aios/schedule.py` не запишет расписание с
нарушением, `aios/balance.py` ловит баланс.
