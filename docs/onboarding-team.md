## О чём проект в пяти строчках

Хакатон AIOS (ПАО «Татнефть»), **трек 2**. Модель Z — гидродинамическая модель
месторождения на 103 скважины. Наша система должна выдать `wells_schedule.inc`
(режимы скважин с 01.01.2007 по 09.2025) и **заявленное значение ЧДД**.
Организаторы один раз пересчитают наше расписание на своей модели. Разойдётся
больше чем на пару процентов — дисквалификация. Первая контрольная точка 17.08.

Дальше: `docs/task.md` — задача и критерии, `PLAN.md` — план, `CLAUDE.md` — правила
работы, `GIT.md` — правила коммитов.

## Развернуться

1. **Материалы организаторов.** В репозитории их нет (дек — 78 МБ). Скачай из
   канала: `Model_Z_final_OPM.zip` и `CHDD_PYTHON.zip`, распакуй по
   `docs/materials.md`. Проверка: `vendor/Model_Z_OPM/Model_Z.data` и
   `vendor/CHDD_PYTHON/chdd_model.py` на месте.

2. **Окружение.**
   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements-dev.txt
   ruff check . && pytest -q
   ```
   Всё зелёное — можно работать. Красное на чистом клоне — пиши сразу, это наш баг,
   а не твой.

3. **Симулятор.** `docs/setup-simulator.md`. Либо apt-пакет OPM Flow, либо
   `docker build -t aios -f docker/Dockerfile .` — образ несёт и симулятор, и
   рантайм. Docker-сборка ещё ни разу не выполнялась (на машине автора нет Docker),
   так что первая сборка — заодно и её проверка; если упадёт, чини и коммить.

## Первая задача: базовый прогон

Это самое ценное, что сейчас можно сделать: пока нет ни одного расчёта, у нас нет
ни точки отсчёта, ни данных для суррогата.

```bash
python scripts/build_case.py            # соберёт runs/base/RUN.DATA из config.toml
scripts/run_flow.sh runs/base/RUN.DATA 8   # 8 — число процессов
```

Базовый кейс — история организаторов как есть, добавлена только наша
SUMMARY-секция (`Model_Z_summary.inc` в поставке пустой, без неё симулятор не
выгрузит ничего).

Дальше — разбор:

```python
from aios import config, economics, margin, summary

settings = config.load()
rows = summary.monthly_rows("runs/base/RUN", fluids=settings.fluids)

problems = summary.sanity_problems(rows)
print(len(problems), problems[:10])

result = economics.compute_npv(rows, headers=economics.REQUIRED_COLUMNS,
                               start_date=settings.economics.start_date.isoformat())
print("ЧДД базового сценария:", result.chdd_m)
```

**Что проверить прежде, чем радоваться числу.** Симулятор не падает на том, чего
не понял, — он это пропускает и считает дальше:

1. в логе нет строк про игнорирование ключевых слов (`run_flow.sh` печатает их
   отдельным блоком);
2. `FOPT` на конец истории отличен от нуля и по порядку близок к ориентиру
   организаторов — около 4,8 млн т нефти;
3. профили по нескольким скважинам похожи на историю, а не на прямую линию —
   именно глазами, а не по сводным числам.

**Что прислать:** ЧДД, время счёта, число процессов, характеристики машины и
строку в `docs/experiments.md` тем же коммитом. Время счёта важно не меньше
числа: от него зависит, сколько прогонов мы можем позволить себе на датасет.

## Чего не делать

Три вещи, каждая из которых стоит дисквалификации или дня работы:

- **Не писать свою формулу ЧДД.** Считает только `vendor/CHDD_PYTHON/`, вендоренный
  побайтово. Обвязка — `aios/economics.py`.
- **Не «чистить» отрицательные приращения** в выгрузке симулятора. Методика
  исключает такие строки из экономики целиком, и так же посчитают организаторы.
  Обнулив их у себя, мы завысим свой ЧДД ровно на те строки, которые у них выпадут.
- **Не пересобирать историю SCHEDULE из разобранных структур.** Внутри лежат
  `COMPDAT` — вскрытия пласта во времени. Потеряешь их — скважины останутся без
  соединений, добыча будет нулевой, и симулятор об этом не скажет.

## Как коммитить

Формат и потоки — `GIT.md`. Коротко: `<поток>: <что сделано>`, префиксы
`sim/eco/sch/srg/mas/ui/docs/infra`. Перед коммитом `ruff check .` и `pytest -q`
зелёные. Каждое инженерное решение — строкой в `docs/decisions.md`, каждый
значимый прогон — строкой в `docs/experiments.md`.
