# Паспорт дня отправки

Идите сверху вниз. Если ожидаемая строка не получена, **не отправляйте пакет**:
остановитесь и разберите расхождение. Все команды выполняются из корня проекта.

## 1. Проверить перед отправкой

| Команда | Ожидаемый итог |
|---|---|
| `git status --short --branch` | только `## main...origin/main`, без других строк |
| `python -m pytest -q` | `0 failed, 0 errors`; допустимы только `passed` и `skipped` |
| `python -m ruff check .` | `All checks passed!` |
| `python scripts/check_package.py` | все 10 строк `[ГОТОВО]`, последняя строка `пакет готов` |
| `python scripts/check_submission.py runs/matched-0995/wells_schedule.inc` | последняя строка `файл пригоден к отправке` |

## 2. Отправить ровно это

- файл: `runs/matched-0995/wells_schedule.inc`;
- ЧДД: **13 133,8 млн руб.**; база: **11 851,8 млн руб.**; прирост:
  **+1 281,9 млн руб. (+10,8 %)**;
- источник файла и расчёта: `docs/submission.md`, разделы 1 и 3;
- источник заявляемого числа: аннотированный тег `submit-2026-08-24.1`.

Число берите из тега командой `git tag -n99 submit-2026-08-24.1`, а не из
памяти, чата или этого листа. В выводе должны быть те же файл и тройка чисел.

## 3. Вставить в сопроводительное письмо

> Файл `wells_schedule.inc` подменяет секцию SCHEDULE целиком; история включена.
> Ответ организаторов на вопрос В-03 не получен.

## 4. Если проверка не сошлась

| Случай | Действие |
|---|---|
| ЧДД отличается | не отправлять; заново выполнить все шесть команд `docs/submission.md`, раздел 3, затем весь раздел 1 этого листа |
| Нет `runs/` | это воспроизводимый каталог под `.gitignore`; получить его шестью командами `docs/submission.md`, раздел 3, не искать в git |
| Нет OPM Flow | использовать Docker-путь из `docs/setup-simulator.md`; если он тоже недоступен, остановиться и сообщить `ЧДД не воспроизведён: симулятор недоступен` |

## 5. В день отправки запрещено

Не пересобирать заявку, не менять `config.toml`, не улучшать число. Любое
изменение после проверки отменяет её результат: повторите раздел 1 целиком.
