# Архитектура МАС

Фактическая архитектура на 22.08.2026. Здесь нет планируемых модулей, выданных
за работающие: у каждого блока указан код и граница подтверждённого поведения.

## Сквозной контур

```text
чужой дек / конфиг
        │
        ▼
deckfiles + deckcheck ──► build_case ──► OPM Flow ──► rows (14 колонок)
                                                        │
                                                        ▼
                                               состояние фонда
                                                        │
              ┌─────────────────────────────────────────┴─────────────┐
              ▼                                                       ▼
      margin + policy                                      surrogate / neural
  диагноз и остановки                                   прогноз уровня и отклика
              │                                                       │
              └──────────────► optimise ◄─────────────────────────────┘
                          совместный поиск по ЧДД
                                   │
                                   ▼
                              planner.enforce
                    общие ресурсы и ограничения объекта
                                   │
                                   ▼
                    schedule.validate + wells_schedule.inc
                                   │
                  ┌────────────────┴────────────────┐
                  ▼                                 ▼
       прогноз суррогата                    полный расчёт OPM
                  │                                 │
                  └──────────► economics ◄──────────┘
                         эталонный расчётчик ЧДД
                                   │
                     CycleResult: прогноз / confirmed
                                   │
                     ┌─────────────┴─────────────┐
                     ▼                           ▼
              explain + web                shapley (офлайн)
           проверяемое объяснение       причинный вклад групп
```

Один автоматический вход собран в `scripts/run_all.py`: базовый кейс → полный
расчёт → цикл МАС → полный расчёт кандидата → подтверждение ЧДД. Целиком на ГГДМ
команда прогнана 20.08 обоими путями (тривиальный бейзлайн и обученный суррогат),
и первый же прогон нашёл разрыв склейки, невидимый юнит-тестам.

**Сдаваемое расписание идёт не этим контуром, и это надо назвать прямо.** Оно
собрано двумя проходами `build_scaled_case.py` → `build_matched_case.py`: сначала
равномерный форсаж, потом уставка каждой скважины опускается до расхода, который
она в этом расчёте действительно взяла (Р-90, Р-93). Правило живёт вне цикла
намеренно: оно не оптимизирует, а **убирает просьбу, которая до пласта не
доходит**, и потому не нуждается ни в суррогате, ни в поиске. Цена — второй
полный расчёт: доля дошедшего измеряется по уже посчитанному сценарию.

Контур с суррогатом при этом не декоративен: 24.08 он впервые дал **подтверждённый
полным расчётом** прирост (`docs/experiments.md`), и кандидат для этого отбирался
шлюзом доверия, а не по величине обещания.

## Роли агентов

Это иерархическая МАС, но не обученная MARL-система и не набор отдельных
процессов. Агенты — детерминированные роли внутри одного воспроизводимого цикла:

| Роль | Что видит и предлагает | Реализация |
|---|---|---|
| скважинный агент | маржа, обводнённость, устойчивость убытка; остановка или множитель режима | `aios/margin.py`, `aios/policy.py`, `aios/optimise.py` |
| координатор | совместный кандидат и дефицит общих ресурсов | `aios/optimise.choose_joint_rates`, `aios/planner.py` |
| экономист | ЧДД всего фонда одной методикой | `aios/economics.py`, вендоренный расчётчик организаторов |
| объяснитель | излагает уже посчитанные факты, не принимает решение | `aios/explain.py` |
| арбитр | подтверждает кандидата полной ГГДМ | `aios/loop.confirm`, OPM Flow |

Скважинные предложения нельзя складывать независимо. На Модели Z отбор ×1.5 и
закачка ×1.6 дали совместный эффект на 369,6 млн руб. выше суммы отдельных
эффектов: действие нагнетателя меняет результат добывающих. Поэтому общий сигнал
поиска — ЧДД фонда, а планировщик стоит над локальными предложениями.

## Цикл решения

`aios.loop.run_cycle` задаёт один порядок операций:

1. Суррогат прогнозирует базовое расписание; по нему считается базовый ЧДД.
2. Совместный координатный поиск перебирает множители добычи и закачки. Каждый
   кандидат оценивается ЧДД **всего** фонда, уже после приведения к общим
   ограничениям, если они заданы.
3. Причинная политика остановок смотрит только на данные до даты решения.
4. Планировщик применяет ограничения по жидкости, источнику и компенсации воды,
   мощности ППД; каждое вмешательство остаётся в `Allocation`.
5. Расписание валидируется, суррогат даёт итоговый прогноз и предупреждения.
6. Полный прогон заменяет оба прогнозных числа: базу и кандидат. Только после
   `loop.confirm` у `CycleResult.confirmed` значение `True`.

Координатный поиск не обещает глобальный оптимум. Его гарантия уже и проверяема:
один шаг не принимает кандидата хуже текущего по используемой безопасной целевой
функции. Текущий оптимум МАС полным расчётом оказался хуже ручного сценария и
для заявки не используется.

## Суррогат и шлюз доверия

Нейросетевой суррогат — MLP по скважинам с разложением «тривиальный уровень +
отклик на управление» (`aios/neural.py`). Для каждого выхода одновременно
обучается Ridge-бейзлайн; train/test делятся целыми сценариями. Артефакт хранит
метрики, seed, версии библиотек, SHA-256 датасетов, опорное расписание и область
сценариев.

Шлюз состоит из независимых проверок:

| Контур | Где действует | Состояние |
|---|---|---|
| качество модели: MLP лучше Ridge, положительный `R²` отклика и медианный `Skill_MAE` | загрузка модели до цикла и до дорогого прогона | подключён; артефакт от 23.08 (пять пакетов) порог проходит |
| роль, дата, физика, известный фонд, диапазон управляющих множителей | сборка и оценка расписания | подключён |
| совместная типичность сценария по расстоянию до обучающих режимов | внутри `choose_joint_rates` через `TrustRegion` модели | подключена; штрафует совместно нетипичный кандидат |
| конформный запас оптимизма `B_J` | API `aios/trust.py` | реализован; калибровать не на чем — на ручных сценариях остаток отрицателен, на кандидатах поиска положителен, пар второго семейства две из девяти (24.08) |
| полный расчёт кандидата | OPM Flow + `loop.confirm` | единственный окончательный арбитр |

Отсутствующая мера не равна нулю. Некалиброванный запас в UI подписан как
«кандидат обязателен к полному расчёту». Сценарное расстояние — guardrail, а не
гарантия для кандидата, специально выбранного оптимизатором за высокий прогноз.

## Общие ограничения

`planner.enforce` применяет правила уровня объекта, которых не видит отдельная
скважина:

- предел суммарной добычи жидкости;
- доступность добытой и сторонней воды, целевой диапазон компенсации;
- предел суммарной закачки системы ППД;
- экономический порядок сокращения добывающих режимов.

Неизвестное ограничение не выдумывается: `0`/`None` в конфиге означает «не
задано» и ничего не режет. Фактическая мощность ППД остаётся вопросом к
организаторам, поэтому реализуемость заявляемого форсажа не подтверждена нашим
стендом.

Жёсткая проверка `aios/schedule.py` выполняется до записи файла: порядок дат,
положительные давления, предел дебита, взаимоисключающие роли, известный фонд.
После ГГДМ `aios.summary.sanity_problems` проверяет накопленные и месячные
величины, соотношение нефти и жидкости, давления и отрицательные приращения.

## Контракты между слоями

| Граница | Контракт |
|---|---|
| дек → управление | `deck.Schedule`, `deck.ScheduleStep`, `ProducerControl`, `InjectorControl` |
| управление → кейс | валидированный `wells_schedule.inc`, `run.Case` |
| ГГДМ → экономика | 14 колонок расчётчика; строка = скважина × месяц |
| экономика → диагноз | `economics.NpvResult`, `margin.WellVerdict` |
| обучение → цикл | `neural.NeuralBundle` с отчётом качества и происхождением |
| цикл → UI/CLI | `loop.CycleResult`, где источник результата закреплён полем `confirmed` |
| полные коалиции → вклад | `shapley.Coalition` с явным `source` |

Имена файлов чужого дека не являются контрактом. `aios/deckfiles.py` находит
секции по структуре `INCLUDE`, `aios/deckcheck.py` возвращает коды проверок, а
не пытается догадаться и продолжить. Переносимость проверена на открытых деках;
валидационный кейс организаторов ещё не получен.

## Объяснимость и LLM

Языковая модель не управляет скважинами и не придумывает обоснование. На вход ей
передаётся `Evidence` из уже рассчитанного `CycleResult`: факты, решения,
ограничения и деньги. На выходе проверяются все числа и связанные пары
«сущность–значение»; ответ с новым числом отвергается целиком. Отпечаток фактов,
модель и источник (`model`, `cache`, `template`, `rejected`) видны в UI.

При отсутствии ключа, отказе API или неверном ответе решение не пропадает:
используется явно подписанный шаблон. Живой вызов API ещё не выполнялся, поэтому
реализованный слой и его внешний интеграционный прогон разделены в плане.

Качество объяснений измеряется отдельно (`aios/explain_quality.py`): ASR, DTC и
NTI не смешиваются с точностью суррогата или величиной ЧДД.

## Причинный вклад групп

Маржа скважины — бухгалтерское разложение, не credit assignment. Причинный вклад
задаётся коалиционной игрой: `v(S)` — полный ЧДД, когда группы из `S` переведены
на кандидатную политику, остальные оставлены на baseline. Для трёх групп нужны
все `2³ = 8` расчётов; `aios/shapley.py` считает точные значения Шепли,
проверяет `Σφ = v(N) − v(∅)` и условные синергии пар.

Механизм и план восьми кейсов готовы. Физические прогоны коалиций выполняются на
машине с OPM; до их завершения архитектура не заявляет численный вклад групп.

## Что ещё не подтверждено

- сквозной `scripts/run_all.py` на реальной ГГДМ;
- обученный суррогат, проходящий текущий порог по отклику;
- найденный МАС оптимум, улучшивший ручной сценарий после полного расчёта;
- живой ответ LLM API;
- мощность системы ППД и валидационный кейс организаторов;
- численный результат полного плана коалиций.

Эти пункты не меняют состав архитектуры, но ограничивают утверждения о её
физической эффективности. Актуальные внешние блокеры ведутся в `BLOCKED.md`,
числа прогонов — только в `docs/experiments.md`.
