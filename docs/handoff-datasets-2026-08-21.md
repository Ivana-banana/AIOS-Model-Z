# Сопроводительная записка к `data.7z` (21.08.2026)

Архив `data.7z` в корне репозитория — четыре датасета DoE, собранные машиной А
20.08 в 14:53 исправленным сборщиком (после `42fec5d`). Распаковывается в
каталог `data/` с готовыми именами: `7z x data.7z`. Распакованные — 290 МБ,
`/data/` в `.gitignore`, обратно в git они не поедут.

Ниже три вещи, без которых замер получится не тот. Порядок важен: пункт 1 —
самая частая ошибка, пункт 2 — самая незаметная.

## 1. Учить на объединении всех четырёх, а не на одном пакете

```
python scripts/train_surrogate.py --model mlp --dataset \
  data/dataset-injection.csv data/dataset-all-near.csv \
  data/dataset-all-wide.csv data/dataset-periods.csv
```
и та же команда с `--model linear`.

Причина измерена, а не предполагается: модель, обученная на одном пакете по
нагнетателям, помечает «нет в обучающем датасете» **любое** расписание, включая
историческое (71 предупреждение). Один пакет покрывает одну ось управления —
детектор диапазона честно сообщает, что всё остальное вне обучения.

`load_datasets` разводит одноимённые сценарии по имени файла, поэтому порядок
файлов в команде на результат не влияет, а вот пропуск любого из них — влияет.

## 2. Метрики — только с 01.01.2007, и в скрипте это уже так

До `control_start` история одинакова во всех сценариях и по входу, и по отклику:
метрика, посчитанная по ней, меряет память, а не обобщение — и выходит красивее
настоящей. `train_surrogate.py` передаёт `control_start` из `config.toml`
(`case.control_start = 2007-01-01`) в `train()`, который отсекает по нему
**тестовые** строки (`aios/neural.py:364`); учимся при этом на всём горизонте.

Что с этим делать получателю: ничего не менять и проверить по выводу — скрипт
печатает строку «метрики считаны на N строках с 2007-01-01». Нет даты в выводе —
значит метрики посчитаны по всему горизонту, и сравнивать их с нашими нельзя.

## 3. Отпечатки — что файлы доехали целыми

Первые 16 знаков sha256; сверено на источнике 21.08 распаковкой этого самого
архива, а не взято из прошлого прогона.

| файл | байт | sha256 (первые 16) |
|---|---:|---|
| `data/dataset-injection.csv` | 70 795 084 | `7346a040292bb993` |
| `data/dataset-all-near.csv`  | 73 415 154 | `c6be997163d058a3` |
| `data/dataset-all-wide.csv`  | 73 522 608 | `a883ecdbfa9e6bf0` |
| `data/dataset-periods.csv`   | 72 345 564 | `e5d1aa635215c6cd` |

Проверка на стороне получателя:

```
sha256sum data/dataset-*.csv | cut -c1-16          # bash
Get-FileHash data\dataset-*.csv -Algorithm SHA256  # PowerShell
```

Полные хэши всех использованных датасетов `train_surrogate.py` кладёт в
`artifacts/surrogate-metrics.json` (`training.datasets`) и печатает в конце
прогона — именно они идут в запись `docs/experiments.md`, а не эти сокращённые.

## Чего эта записка не покрывает

Совпадение отпечатков говорит только о целостности передачи. Оно **не**
подтверждает, что пакеты досчитаны полностью и что фикс сборщика доехал: это
отдельная проверка — доля строк с пустым `production_multiplier` /
`injection_multiplier` обязана совпасть с долей месяцев до `control_start`
(на Модели Z 145 из 370, около 39 %). Доля 0 — датасет собран старым сборщиком.
