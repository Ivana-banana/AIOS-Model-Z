## Что сверено на нашей стороне (21.08)

**Аудит «молча игнорируемых» ключевых слов — пересечений с Модели Z нет.**
Из отчёта извлечены все 64 некритических записи `UnsupportedFlowKeywords.cpp` и
пересечены с полным списком ключевых слов дека (`Model_Z.data`, `_grid`, `_edit`,
`_init`, `_props`, `_regs`, `_sch`). **Пересечение пусто.** То есть заявленный
риск «Flow тихо выбрасывает часть дека» на Модели Z не реализуется: дек написан
на узком подмножестве, и единственное неподдерживаемое ключевое слово — то, про
которое мы знаем, `PINCHREG`.

Воспроизводится так:

```bash
sed -n '/^## 5\./,/^## 6\./p' docs/manus/opm-pinch-vs-tnavigator.md \
  | grep -oE '^\| `[A-Z0-9]+`' | tr -d '|` ' | sort -u > /tmp/manus_kw.txt
cd vendor/Model_Z_OPM && cat Model_Z.data Model_Z_*.inc \
  | grep -oE '^[A-Z][A-Z0-9]{1,7}' | sort -u > /tmp/deck_kw.txt
comm -12 /tmp/manus_kw.txt /tmp/deck_kw.txt   # пусто
```

**`PINCHREG` в деке — две записи с порогом 2 м, `PINCHNUM` отсутствует,
`GRIDOPTS` разрешает 3 pinch-региона, рядом `MINPV 1`.** Отчёт подтверждает, что
`PINCHREG` в OPM помечен как **критический**, а `--parsing-strictness=low` лишь
понижает ошибку до предупреждения, не реализуя региональный алгоритм. Наша
формулировка в `docs/decisions.md` и `docs/report.md` теперь опирается на
исходники OPM, а не на наблюдение за логом.

**Issue #3145 объясняет строку, которую мы видели, но не объясняли.** В базовом
прогоне без `PINCH` лог содержит `1 pinch-out connection generated`
(`runs/base/RUN.PRT`). Отчёт связывает это с зафиксированным поведением Flow:
pinch-соединения создаются с параметрами по умолчанию даже при отсутствии
`PINCH`. Масштаб (1 против 27 696) косметический, но это была необъяснённая
строка в логе.

**Чего отчёт не даёт.** Прямого сравнения «OPM против тНавигатора» по режимам
`PINCH` в нём нет и быть не может: спецификация тНавигатора публично не
издаётся. Это ограничение отчёт проговаривает сам — и оно означает, что наш
разрыв 5,0 % внешними источниками не закрывается, только измерением.
