# Инструкция от чистого клона: протокол буквального исполнения

Задача Б27, выполнено 23.08.2026 на машине Б. Проверялись `docs/submission.md`,
раздел 5, и `README.md` — **буквально, командой за командой**, без подстановки
знания о проекте.

**Почему именно эта машина.** У неё нет ни дека, ни датасетов, ни Docker, ни
WSL — то есть она и есть проверяющий. Автор инструкции, у которого всё стоит,
систематически не видит шагов, выполненных когда-то и молча.

Исходы размечены тремя метками, как требует задача:

* **прошло** — команда выполнилась, результат такой, как обещано;
* **упёрлось в отсутствующее** — нужен дек, симулятор, Docker или ключ. Законно,
  но обязано быть названо до шага, а не обнаруживаться на нём;
* **не исполнимо буквально** — команда предполагает то, чего в тексте нет.
  Только это и чинилось.

**Итог: 12 шагов, из них «прошло» 8, «упёрлось в отсутствующее» 2, «не исполнимо
буквально» 4 — все четыре исправлены.**

## Что делалось

```bash
git clone C:/Users/.../AIOS aios      # клон настоящий, не копия каталога
py -3 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pytest
.venv/Scripts/python.exe -m ruff check .
```

Клон делался дважды: в глубокий путь (`…/AppData/Local/Temp/claude/…`) и в
короткий (`C:\aios-check`). Разница между ними и оказалась первой находкой.

## Четыре дефекта и что с ними сделано

**1. Клон на Windows разваливается при глубоком пути.** Два файла в
`manus-answered/` имеют имена длиной 92 и 102 символа; вместе с длинным путём
назначения они выходят за предел 260 символов, `git` не создаёт их и **отменяет
весь checkout** — рабочее дерево остаётся пустым. Это худший из возможных исходов:
клон «succeeded», а файлов нет.

*Сделано:* в `docs/submission.md` добавлен блок «что нужно иметь до начала», где
названы короткий путь и `git clone -c core.longpaths=true`. Файлы не
переименованы намеренно — это материалы внешнего разбора, и менять их имена
задним числом значило бы менять сам артефакт.

**2. `py -3.11` требовал версии, которой у проверяющего может не быть.** Проект
объявляет `requires-python = ">=3.11"` и живёт на 3.14, а инструкция требовала
ровно 3.11.

*Сделано:* `py -3` в `README.md`, рядом — вариант для Linux/macOS и явная строка
«Python 3.11 или новее».

**3. `Rename-Item vendor\Model_Z vendor\Model_Z_OPM` не выполняется.** Ошибка
воспроизводится всегда: PowerShell ждёт имя, а не путь. Команда стояла в двух
местах — `README.md` и `materials/README.md`, — и, судя по формулировке, ни разу
не была исполнена буквально.

*Сделано:* исправлено в обоих местах, рядом добавлен `unzip`/`mv` для Linux.

**4. `requirements.lock` на Windows не ставится, и инструкция об этом молчала.**

*Сделано:* сказано прямо в `README.md`, в разделе «Установка», **до** того, как
читатель попробует команду.

## Чего эта проверка не делает

* **Не проверяет расчёт.** Симулятора на машине нет; заявляемое число этой
  проверкой не воспроизводится и не подтверждается — она про инструкцию, а не
  про ЧДД.
* **Не проверяет Docker-путь.** `docker build` не запускался: Docker на машине
  нет. Всё, что сказано про образ, остаётся непроверенным здесь и проверяется на
  машине А (`docs/setup-simulator.md`).
* **Не заменяет проверку на чужой машине.** Клон делался с локального
  репозитория, а не с GitHub: сеть и права доступа к удалённому репозиторию этой
  проверкой не покрыты.
* **Не гарантирует Linux.** Все шаги выполнялись на Windows 10; для Linux даны
  команды, но буквально они здесь не исполнялись — кроме `bash scripts/run_flow.sh`,
  который отказал ожидаемо.
